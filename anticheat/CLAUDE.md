# StrazhAC — контекст проекта для Claude

Серверный античит для **Paper 1.21.11** (Java 21) для сервера владельца репозитория.
Работа шла в облачной сессии Claude Code. Этот файл переносит весь контекст в новые
(локальные) сессии. Подробный контракт для написания проверок — `docs/DEV_GUIDE.md`,
описание для админа — `README.md`.

## Как работать с владельцем

- Пишет по-русски — отвечай по-русски, коротко и по делу.
- Следи за расходом: владелец на подписке Pro. **Не запускай агентов и workflow без
  явной просьбы**, работай сам и экономно.
- Ветка разработки — `claude/dreamy-edison-h27f8t`. После изменений: сборка и тесты,
  копия jar в `release/`, коммит, пуш. PR создавай только по просьбе.

## Что требуется от античита

- Ловить всё, что вообще можно поймать на сервере, **кроме X-ray**: бой, аим, движение,
  мир, инвентарь, пакеты. Включая приватные и платные клиенты, в том числе с
  ИИ-ротациями, которые обходят античиты на топовых серверах. Отсюда упор на
  детерминированные инварианты протокола (порядок пакетов в тике, эхо поворотов,
  углы в UseItem), а не только на статистику.
- **Не кикать за кастомные машины на Skript** (это жёсткое требование):
  - сиденья — сущности `item_display` с тэгами `car_seat`, `car_main`, `car_id_*`
    (мопеды — `moped_main`); полный список в `vehicles.seat-tags` в `config.yml`;
  - сервер каждый тик телепортирует сиденья и шлёт игроку
    `ClientboundPlayerRotationPacket(dy, true, 0, true)` (относительный поворот);
  - Skript задаёт скорость (velocity) при авариях и взрывах, после высадки телепортирует
    игрока к двери, отменяет Q (гудок), F (фары) и ПКМ ключом;
  - `gun.sk` — оружие с лучом по ПКМ.
  - Как это учтено: проверки движения и аима отключены, пока игрок сидит на транспорте.
    После высадки идёт льготный период (`vehicles.dismount-grace-ticks`, для кастомного
    транспорта он вдвое длиннее). Эхо поворотов исключается из анализа аима. Скорость и
    телепорты от сервера привязаны к транзакциям.

## Сборка и тесты

```
./gradlew build                 # нужен доступ к repo.papermc.io и repo.codemc.io
./gradlew test                  # 21 тест: физика, транзакции, трекеры, смоук всех проверок
cp build/libs/StrazhAC-1.0.0.jar release/
```

- Зависимости: `paper-api 1.21.11-R0.1-SNAPSHOT` и `packetevents-spigot 2.14.0`, обе
  compileOnly. PacketEvents ставится на сервер отдельным плагином (`depend: [packetevents]`).
- В облаке репозитории Paper/CodeMC были закрыты, поэтому сборка шла офлайн:
  `-PlocalLibs=<папка с paper-api.jar и packetevents.jar>`. Локально этот режим не нужен.

## Архитектура (кратко, подробно — docs/DEV_GUIDE.md)

- **Потоки.** Все пакетные трекеры и проверки игрока работают в его Netty event loop
  (однопоточно). Мир, Bukkit API, движок движения и наказания работают в главном потоке
  через `data.queueMain(...)`. Очередь разбирается на `ServerTickStartEvent` и перед
  раздачей Bukkit-событий. Пинги отправляются на `ServerTickEndEvent`.
- **Транзакции** (`player/TransactionManager`). Ping/pong каждый тик, id случайные
  32-битные (читы вычисляют античит по диапазону id). Пинг отправляется и сразу после
  velocity, телепорта и PlayerRotation. Окно «до/после»: `lastSent()` / `nextPostSeq()`,
  `runOnConfirm`. Базовый RTT — 10-й перцентиль. RTT по ядру ОС (`util/NetUtil`, epoll
  `tcpInfo`) работает только без прокси.
- **Инварианты 1.21.2+.** Порядок пакетов в тике:
  `[слот] [действия] [PlayerInput] [спринт] [движение] [ClientTickEnd]`.
  Клики и закрытие окон приходят только между тиками. На PlayerRotation клиент сразу
  отвечает эхом Look (onGround=false). Открытие экрана отпускает все клавиши. В первом
  тике после закрытия экрана удар невозможен. Углы в UseItem равны углам тика.
- **Зонд тихого аима** (Aim D). Сервер шлёт PlayerRotation(0 rel, 0 rel). Silent-ауру
  выдаёт треугольная невязка эха больше 8°.
- **Ловушка** (`honeypot/HoneypotService`). Фейковый игрок только в пакетах, строго за
  спиной подозреваемого: запись в табе, подписанный скин другого игрока онлайн,
  правильная схема UUID, id из `Bukkit.getUnsafe().nextEntityId()`.
- **Движок движения** (`sim/engine/BoundsEngine`, «модель границ», главный поток):
  - верхняя граница горизонтальной скорости: инерция·трение + ускорение, +0.2 при
    спринт-прыжке, плюс скорость от сервера и толкание;
  - вертикаль по гравитации, силе прыжка, высоте шага и формуле левитации;
  - подмена земли и вход в блоки;
  - направление ускорения сверяется с клавишами из PlayerInput (Strafe A);
  - точная физика элитр без фейерверков, FastClimb;
  - в неопределённых ситуациях ставятся флаги `Uncertainty`, и проверки молчат.
  Это не полная попакетная симуляция, как у Grim.
- **Проверки.** Класс с `@CheckInfo` реализует хуки из `check/hook/*`. Чтобы проверка
  заработала, класс нужно добавить в список `ALL` своей категории
  (`check/impl/<категория>/*Checks.java`). Параметры читаются через `cfg(key, def)` и
  сами дописываются в `config.yml → checks`.
- **Наказания.** `punish/PunishmentManager` срабатывает с задержкой
  (`punishments.delay-seconds`), даже после выхода игрока. `punishments.enabled: false`
  оставляет только алерты.

## План локального тестирования

1. Поднять тестовый сервер: Paper 1.21.11, PacketEvents (Modrinth), StrazhAC.
   В конфиге `punishments.enabled: false`.
2. Проверить запуск: нет ошибок в консоли, `config.yml` с разделом `checks` создаётся,
   работают `/strazh checks`, `/strazh info`, `/strazh debug`.
3. Поставить Skript и скрипты владельца (машины, gun.sk; файлы попросить у него).
   Проверить, что катание, аварии, высадка и стрельба не дают флагов.
4. Прогнать ботов (mineflayer; если он не поддерживает 1.21.11, поставить
   ViaVersion/ViaBackwards). Сценарии: обычная игра (ложные срабатывания) и «читерские»
   движения (speed, fly, timer, reach, аура). Важно: физика ботов не ванильная, и
   ClientTickEnd они, скорее всего, не шлют. Окончательная проверка на ложные
   срабатывания — живая игра владельца на `localhost`.
5. Живая игра владельца 10–15 минут: ходьба, прыжки, плавание, лестницы, лёд, слизь,
   элитры, машины, стрельба, бой. Читать `plugins/StrazhAC/logs/` и подстраивать пороги.

Где ложные срабатывания наиболее вероятны (проверить в первую очередь):

- BadPackets M — моды третьего лица, которые поворачивают игрока при использовании
  предмета (Shoulder Surfing и похожие);
- PacketOrder A и Inventory A/B — клиенты с модами;
- Timer A на нестабильном интернете;
- Aim A — экспериментальная;
- движение рядом с транспортом и после высадки.

## Известные ограничения и идеи на будущее

- Не проверяются элитры с фейерверком и тризубец.
- Bedrock-игроки (Geyser) по движению и бою только логируются.
- RTT по ядру не работает за BungeeCord/Velocity.
- `WorldScan` на каждый пакет движения читает блоки в главном потоке. Если будет
  нагрузка — кешировать.
